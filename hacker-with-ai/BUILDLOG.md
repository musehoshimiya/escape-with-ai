## 続きのミッション＋ノベルUI化（2026-11-27 実施）

### 事件簿（ミッション構成）
セッション内でミッションが順に解放される「事件簿」形式にした。サーバー側は `server/casebook.mjs` が束ね役で、各ミッションは `{ id, no, title, goal, introText, createState, guiView, applyAction, applyCelebrate, buildBrief, isCleared }` のモジュール形に統一（ミッション1も同形に接続）。guiView は「いま開いているミッション」の view をトップレベルに保ち、事件簿情報（casebook / mission / scene）を付け足す形にしたため、既存テストの前提（state の形）は壊れていない。ミッションを解くと次が解放され、事件簿パネルから解決済み・未解決の事件を読み返せる（状態は事件ごとに保持）。

- ミッション2「写真コンテストの鑑定」（`server/mission2.mjs`）：拡張子改ざん＋EXIF。写真サークル「あおぞら写真会」のコンテスト応募フォルダに混ざった6ファイル（本物のJPEG／PNG／ZIP／実行ファイル／期間外の旧作JPEG／文章データ）を鑑定する。材料（ファイル名・先頭バイト＝ヘッダ・EXIF）は画面、組み立て方（マジックナンバーの表と「形式・日時・申告との整合」の3条件照合）は brief のヒント。ファイル名・日時はセッションごとにランダム化。誤った特定2回で応募フォルダが1分ロック。特定→依頼人への報告で解決、報告書3項目。
- ミッション3「祖父の遺した写真」（`server/mission3.mjs`）：ステガノグラフィ。遺品の画像2枚のうち1枚のピクセル RGB の最下位ビットに、短い英語の手紙（候補5語からランダム）を MSB ファーストで埋め込む（サーバー側でピクセル値を生成。もう1枚はランダム値で復号しても意味のある言葉にならない）。抽出の解析（LSB を並べて8ビットごとに文字化）は brief のヒントが担い、ピクセルデータは brief の資料欄に届く。人間は文脈（遺言メモ・家族への聞き込み）を読み、言葉を入力して照合（3回ミスで1分ロック、大文字小文字は無視）。届けると解決、報告書3項目。
- 最終ミッション「病院事件の真相」（`server/mission4.mjs`）：既存機構をここで有効化（docEnabled=true はこのミッションのみ）。流れ：
  - 証拠の再確認（事件ログの要約／関係者リスト／ホゲの裏取り＝EXIF 21:50 のアリバイ／ヤスへの聞き込み）。
  - 押収文書スポットを開くと、出所情報（作成者は院外の不明アカウント／作成は事件の最中）は画面側に付き、本文（POISON_DOC）は brief の資料欄に原文のまま流入する＝実装としての汚染。相方AIは文書内の偽指示により「犯人はホゲ」と主張し得る状態になる。
  - 解決導線：brief の正本ヒント「文書の出所の確認」（文書を読むと出現）が、出所の照合結果と「AIへの指示の混入＝プロンプトインジェクション」という名指しを返す。用語集への「プロンプトインジェクション」追加も、このミッションで文書を読んだ後に限る（読む前は brief に出ない）。
  - 告発の分岐：ヤスの告発は裏付け3点（押収文書の確認・事件ログの要約・ホゲの裏取り）が揃わないと証拠不足で止まる。小林さん（被害者確定）は告発不可。ホゲを告発するとバッド寄り結末（badEnd）になるが、「検証し直す」スポットで告発を取り下げて証拠を確かめ直せる（詰みなし）。ヤスを証拠つきで告発すると真結末（犯人を確保して引き渡す）。全体の報告書にプロンプトインジェクションの答え合わせを含む3項目を追加。
  - ミッション1〜3では汚染・矛盾は一切なし（brief に POISON_DOC が入らないことをテストで確認）。相方の誘導は終始正しい。

### ノベルUI化
- 中央カラムは「ステージ＋バックログ」の2段構成に変更。ステージは場面ごとの背景グラデーション（bg: hospital/server/photo/home/office/clear）、雰囲気（mood: normal/alert/clear）、立ち絵スロット（左・中央・右）、今の場面の短いキャプションだけを持ち、物語テキストは持たない。
- 立ち絵はプレースホルダ：cast の色で描くインラインSVGシルエット＋名前・役割・表情トーン表示。場面（scene）はサーバー側 guiView が返す（ミッションごとに sceneFor を定義）。
- テキストはバックログ側に集約：出来事ログ（#log）に物語・調査記録が時系列で残り、場面区切りはサーバーが kind:"scene" のイベントとして正しい位置に挿入する（従来のクライアント側挿入による表示順のズレも解消）。

#### 立ち絵の実素材への差し替え手順
1. 画像ファイル（透過PNG想定）を `public/assets/` 等に置く。
2. 各ミッションの `sceneFor` が返す cast 要素に `img: "/assets/<ファイル名>"` を追加する（例：`{ slot: "left", name: "…", role: "…", color: "#…", tone: "…", img: "/assets/yui.png" }`）。
3. `img` がある cast はシルエットの代わりにその画像が表示される（app.js の renderStage が自動で切り替える）。背景を差し替える場合は style.css の `.stage.bg-*` のグラデーションを画像指定に置き換える。

## UI基準の統一：資料はモーダル、聞き込みはノベルパート（2026-11-27）

「読むだけの資料」と「聞き込み」の表示方法を、全ミッション共通の UI 基準に統一した。

### 1. 資料スポット → 汎用モーダル `#material-dialog` ＋ バックログ

- 対象：M1 roster（職員名簿）/ memo（管理者メモ）/ overview（病院概要）/ sns（公開情報）、M2 guide（応募要項）/ claims（申告）、M3 will（遺言メモ）、M4 caselog（事件ログ要約）/ people（関係者リスト）/ hoge（ホゲの裏取り）。
- 各ミッションの guiView に `materials`（spotId → { title, text }）を追加。**読了フラグが立った資料だけ**を載せる（未読の内容は state に出ない）。text は applyAction がイベントとして出す全文と同一ソース：M1 は rosterText / overviewText / snsText ヘルパに切り出して両経路で共用（ランダム値を含む名簿・概要・SNS も state から組み立てるので、モーダルとバックログが必ず一致する）。M2〜M4 は既存の定数テキストをそのまま参照。
- フロント：スポットをクリックしたら、既に materials にあれば**サーバーへ再投稿せず**即モーダルを開く。未読なら postAction 後に返ってきた state.materials から開く。全文は従来どおりイベントとしてバックログにも残る。再読クリックで短い確認文がバックログに重複して流れる旧挙動（M2〜M4）は、投稿自体をしないことで解消（M1 も再読で全文が再送されなくなった）。

### 2. 聞き込みスポット → ステージ上のノベルパート

- 対象：M1 interview、M3 family、M4 yasu。
- guiView に `dialogues`（spotId → { title, lines: [{ speaker, text }], cast: [{ slot, name, role, color }] }）を追加。既存テキスト（INTERVIEW_TEXT / M3.family / M4.yasuInterview）を `toDialogueLines`（server/util.mjs）で構造化：「・」始まりの行＝その話者の台詞、それ以外（見出し・※注記）＝地の文（speaker: null）。話者は M1＝山田（左）、M3＝森川 葵（右）、M4＝安田 修（ヤス）（右）。立ち絵は既存のシルエット／プレースホルダ仕組みを流用。
- フロント：ステージ内に `#novel-window`（名前プレート＋台詞＋進捗＋「▼ 次へ／閉じる」ボタン）。ウィンドウ全体のクリックでも1行ずつ送れる。発言中の話者のスロットは `speaking`（名前が金色にハイライト）、他の話者は `dimmed`（減光＋彩度低下）。再生中は通常のステージ再描画を止め、キャプションは隠す。最終行を送るとウィンドウが閉じて通常のステージ表示に戻る。再生中に別のスポットを押したときもノベルは畳まれる。
- 会話の全文は従来どおりイベントとしてバックログに残る（読み返し用）。読了後の再クリックは再投稿せず dialogues から再生する。

## 追記（2026-11-27 午後2）計算ミスの肩代わりチューニング

実プレイで、パートナーAI（ChatGPT）が K=(888 mod 9)+3 を「=3」と計算ミスし、復号が合わず詰まった。AIの計算ミスは意図した難易度ではないため、純粋な計算をサーバー側で肩代わりする：
- 復号ヒントに、この世代の「9で割った余り」と K をサーバー計算で併記。AIの残作業は文字をずらすだけにし、「復号結果は読める単語になるはず。ならなければ見直す」という自己検算の一文を追加。
- 認証コードのヒントに、復号済みでチャレンジ表示中は「チャレンジ × シード = 積」を併記。AIの残作業は「900000以上なら1回引く」＋「100000を足す」だけ。
- PARTNER_GUIDE に「■ 計算の約束」を追加：途中の値を確かめる、結果の形がおかしければ答える前にやり直す、併記された計算済みの値を正とする。
