# hacker-with-ai

**自分のAIといっしょに探偵をするゲーム。**（作業タイトル：『相方AI探偵事務所 〜病院からの依頼〜』は仮題）

プレイヤーと相方AIは探偵事務所のコンビ。最初の依頼は病院から――「システムが何者かに乗っ取られたので、調べて取り戻してほしい」。
人は GUI で資料やメールを調べ、関係者に聞き込みをし、AI は CUI（curl）から同じセッションに参加して、解析・照合・計算の相方を務める。
探偵ごっこの体裁で進むが、調査の手つきの正体は現実のセキュリティの考え方。クリア後の「事件の報告書」で答え合わせをする。
企画の正本は GitHub の musehoshimiya/escape-with-ai Issue #3。前作 escape-with-ai は PoC（断面の実証）で、本作はその型を土台にした本格版。

## 設計の柱

- **画面には材料、AIには組み立て方**：断片の値は画面の資料に散らし（ダミーも混ぜる）、組み立て方は AI の brief 側に置く。進行には会話が必須になる。
- **対象は中学生〜初学者**：前提知識ゼロで入れる文言にし、専門用語は用語集（AIに聞ける仕組み）に逃がす。難しさは「知識の量」ではなく「考える手順」で付ける（断片化、ノイズ、証言の照合、失敗時のロック）。
- **探偵の仕事＝セキュリティの手つき**：聞き込み・身辺調査はソーシャルエンジニアリング／OSINTと表裏。写真のメタデータ（EXIF）で証言の裏を取る場面もある。学習の着地はすべて防御側（騙され方を知って守る）で、現実の侵入手順の指南にはしない。対象は作中の架空の閉じたシステムだけ。
- **相方AIは信頼できる相棒**：ミッション1では AI の誘導は終始正しい。材料の組み立て、計算、証言の照合を任せられる体験を積み上げる。
- **用語はAIにそのまま聞ける**：brief に用語集を含め、合言葉「ゲームの用語：○○」で概念だけを答える約束を参加プロンプトに入れてある。
- **UIはノベル的な読みの体験**：出来事は明朝系のストーリー欄に時系列で残り、読み返せる。調査コンソールの要素（調べる場所、手順、手がかり）はその周りに組み込む。

## ミッション1の流れ

1. 手がかり集め（院内メール・職員名簿・管理者メモ・病院概要・公開情報の調査・聞き込みに断片と証言が散らばる。証言の矛盾や裏付けは AI が照合する）
2. フィッシング判定（通知から本物を1通選ぶ。間違えるとアラート、2回でメール確認がロック）
3. 端末ログイン（断片から組み立てたパスワード。3回ミスで1分ロック）
4. バックアップ復号（暗号文は画面、復号手順と鍵の導き方は brief）
5. 二要素認証（画面のチャレンジと brief のシードからコードを導く）
6. 復旧実行 → 達成キーワードが画面に出て、AI が検証してお祝いする（PoC の celebrate 機構を継承）。クリア後は「事件の報告書」で、使った手つきと現実のセキュリティ概念を答え合わせ

パスワード断片の値、復号対象、認証チャレンジなどはセッションごとにランダム化される。

## 遊び方（参加の仕組み）

前作から継承：

1. 参加画面で名前を入力すると、セッションが発行され、AI 招待プロンプトが表示される
2. プロンプトを自分の AI に貼ると、AI がセッションに参加する。接続方法は AI が自分で選ぶ（curl / MCP ツール / ブラウジング）。どちらも同じセッション状態を触る
3. 詰まったら合言葉で聞く：**「ゲームのヒント：○○」**／用語は **「ゲームの用語：○○」**
4. 復旧に成功したら、画面の達成キーワードを **「ゲームのお祝い：○○」** と AI に話しかけると、お祝いが画面に届く

## 起動（ローカル・Node 版）

```sh
npm start
# → http://localhost:8788 （PORT 環境変数で変更可）
```

外部公開時は `PUBLIC_BASE_URL` に公開 URL を設定すると、招待プロンプト内の URL がそちらになる。
検証用に `GAME_LOCK_MS` を設定すると、ロック時間（既定60秒）を短縮できる。

## Cloudflare へ置く（本番・未デプロイ）

Workers + Durable Objects で動かす構成にしてある（`worker/worker.mjs`、`wrangler.toml`）。セッション1つ = Durable Object 1個で、状態は DO ストレージに保存される。
**現時点ではローカル検証までで、本番デプロイはしていない。**

## API

| メソッド | パス | 用途 |
|---|---|---|
| POST | `/api/sessions` `{name}` | セッション発行。`sessionId` と `joinPrompt` を返す |
| GET | `/api/sessions/:id/state` | GUI 用の状態（調べる場所・手順・メール・キーワード等。秘密の答えは含まない） |
| GET | `/api/sessions/:id/events?since=N` | イベント差分（ポーリング用） |
| POST | `/api/sessions/:id/action` `{spot, ...}` | 人の操作（調べる／聞き込み／判定／ログイン／復号／認証／復旧） |
| GET | `/api/sessions/:id/ai/brief` | AI 用：状態の文章化＋ヒント集＋用語集＋最近の出来事 |
| POST | `/api/sessions/:id/ai/message` `{text}` | AI が画面にメッセージを残す |
| POST | `/api/sessions/:id/ai/celebrate` `{word, text}` | 復旧後、プレイヤーが達成キーワードを AI に言うと AI がお祝いを届ける（一度だけ） |
| GET | `/api/sessions/:id/ai/celebrate-get?word=&text=` | POST できない AI 向けの GET 版お祝い |
| GET | `/api/sessions/:id/rejoin-prompt` | 接続が切れた AI の再参加プロンプト |
| POST | `/mcp` / `/mcp/:id` | MCP（JSON-RPC）。ツール：get_brief / get_events / post_message / celebrate（引数に sessionId） |

セッション ID（12桁 hex）そのものが参加キー。Node 版はインメモリで、再起動すると消える。

## 構成

- `server/mission.mjs` — ミッションの状態・遷移・AI 向け文章化（brief）
- `server/content.mjs` — ゲーム内テキストのデータ集（タイトル・舞台・メール・証言・用語集・報告書。差し替えはここ）
- `server/prompt.mjs` — AI 招待プロンプトの生成（合言葉・用語・お祝いの作法）
- `server/mcp.mjs` — 最小 MCP ハンドラ
- `server/server.mjs` — HTTP サーバー＋API（依存なし、Node 標準のみ）
- `worker/worker.mjs` — Cloudflare Workers 版（DO に状態保存）
- `public/` — 参加画面＋調査コンソール（ノベル的なストーリー表示を中央に置いた画面設計）
- `test/` — ローカル検証スクリプト（API 全フロー／実ブラウザ操作／機構単体）
